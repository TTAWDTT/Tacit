## 2026-09-27 — DuoSum benchmark and communication bound

- Followed the Silo task-instance audit with a minimal task whose answer depends on both agents' private observations: exact sum of two positive private integers, with both agents required to submit the result. Every local value is strictly smaller than the gold sum, so no agent can solve an episode from its own exact observation alone.
- Formalized a deterministic binary-wire lower bound. For input-domain size `M`, any exact protocol in which both agents output `x+y` needs at least `2 log2(M)` worst-case bits; for powers-of-two domains, sending each fixed-width private input once reaches the bound. The proof uses the standard transcript-rectangle property. This is a wire-bit result, not a model-token bound.
- Added generator and 16 pinned cases at widths 4/8/12/16 with one calibration seed and three held-out seeds per width. The pilot protocol freezes the manifest hash, simulator commit, Qwen revision and weight hashes, recipient/submit interaction scaffold, and concise-NL, compact key-value, JSON, and no-communication conditions.
- The next run tests feasibility across widths and whether the format prompts change payloads or receiver behavior. It is not yet a bandwidth-matched sweep or a representative benchmark; multi-turn planning and additional task families remain necessary.
- Ran the four pinned calibration episodes across five arms. Strict per-agent success was 0.25 for scaffold-only and JSON, 0.125 for concise NL and compact key-value, and 0 for no communication. A post-hoc exact arithmetic parser (reported separately from the benchmark evaluator) found semantic answer rates of 0.875, 1.0, 0.75, 0.75, and 0 respectively. All no-communication submissions were wrong.
- The gap is primarily at the terminal interface: for 8-, 12-, and 16-bit inputs, agents often communicated the correct values and computed the correct sum but submitted strings like `723 + 2547 = 3270`, while Silo requires an integer. Do not silently normalize this in the evaluator; track strict tool success and semantic answer correctness as separate outcomes.
- JSON averaged 20.25 UTF-8 payload bytes and 6,187 total model tokens; compact key-value averaged 12.5 bytes but 6,707 tokens. Compact payload length did not imply lower end-to-end token cost. These are four single-seed calibration episodes, not a superiority or scaling result.
