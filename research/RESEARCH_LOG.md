## 2026-09-27 — Initial scoping and public thesis

- Confirmed the project directory was not yet a Git repository and had no project files.
- Surveyed primary sources across alternative-format LLM communication, latent collaboration, emergent language, protocol benchmarks, topology, and current A2A specification.
- Key correction: AutoForm (Chen et al., Findings EMNLP 2024) directly tested alternative-format communication, including an evidence-split HotpotQA setting. Token reduction and private-information necessity are therefore not novelty claims. Its quality/cost response differs by model pair (GPT-4 improves while GPT-3.5 declines on that split), motivating explicit quality-cost curves and current open receiver replications.
- Found existing communication-dependent suites: Silo-Bench (30 algorithmic tasks, 2–100 agents, several topologies) and MT-PingEval (private-information games, fixed token budget divided over turns). Use them before considering new benchmark creation.
- ProtocolBench measures transport/protocol system costs with bytes, latency, quality, and failure recovery, but its scenarios center document QA/tool workflows, queues, safety, and failure storms. Treat it as the instrumentation comparator; do not conflate transport overhead with semantic format efficiency.
- AutoForm's public implementation requires OpenAI and Google API credentials. The inspected local workstation has Python 3.13, PyTorch 2.6 CUDA 12.4, Transformers 5.2, 8 GiB RTX 4060 / ~32 GiB RAM, and no standard Ollama/llama.cpp executable or exposed model API keys. A local HF model with a compatible small runtime is feasible but must be validated before promising an execution path.
- Inspected Silo-Bench's official code: its `C_token_consumption` implementation sums API-reported input + output tokens then divides by rounds, while the README formula describes output tokens. Its tool layer logs P2P payload content but does not add an aggregate wire-byte metric. Our pilot retains input/output totals, task success, rounds, and separately measured UTF-8 message payload bytes; the README/code discrepancy is recorded instead of silently choosing one.
- Added an operational task-conditioned rate-distortion frame, an explicit distinction between mutual information and measured model/system cost, and a break-even equation for amortized codebook setup. These yield predictions about task-critical omission, receiver mismatch, interactive turns, setup horizon, and repair overhead before results are observed.

- Created the first benchmark and baseline plan as hypotheses/design, not reported results.
- Machine feasibility noted: RTX 4060 8 GiB VRAM, ~32 GiB RAM. Plan local experiments around small models and symbolic tasks.

## 2026-09-27 — Interaction calibration v0.2

- Added and pushed a frozen calibration protocol before running it. It separates no added prompt, a generic coordination scaffold, concise-message guidance on top of that scaffold, and a no-communication intervention. The scaffold is included in input-token accounting.
- On the same valid Global Max instance, the scaffold-only arm reached 1.00 success in this single greedy run (7,842 total model tokens; 3 sends, 2 receives, 2 submissions; 18.293 s), while the unconstrained arm reached 0.50 (9,181 tokens; 8 sends, 2 receives, 2 submissions; 63.818 s). The no-communication arm reached 0.50. These are single-instance diagnostics, not robust comparative estimates.
- Concise-NL plus scaffold scored 0.00 (9,432 tokens; no submissions). Every communicating condition emitted the same 46-byte message payload, `My local maximum is 827`; the format hint did not make this receiver's message shorter or change its content. In this run it was associated with repeated self-sends/polling and failure to submit.
- Interpretation: receiver interaction policy can dominate this task's outcome and token cost, while a message-format hint can add prompt cost without changing the wire message. This reinforces receiver-conditioned evaluation and the need to separate control protocol from semantic encoding.
- Reported in `research/INTERACTION_CALIBRATION_V0_2.md`. Next: build multiple held-out instances with verified local-information insufficiency, then run the same interaction policy across varied instances/receivers before any representation frontier claims.

## 2026-09-27 — DuoSum benchmark and communication bound

- Followed the Silo task-instance audit with a minimal task whose answer depends on both agents' private observations: exact sum of two positive private integers, with both agents required to submit the result. Every local value is strictly smaller than the gold sum, so no agent can solve an episode from its own exact observation alone.
- Formalized a deterministic binary-wire lower bound. For input-domain size `M`, any exact protocol in which both agents output `x+y` needs at least `2 log2(M)` worst-case bits; for powers-of-two domains, sending each fixed-width private input once reaches the bound. The proof uses the standard transcript-rectangle property. This is a wire-bit result, not a model-token bound.
- Added generator and 16 pinned cases at widths 4/8/12/16 with one calibration seed and three held-out seeds per width. The pilot protocol freezes the manifest hash, simulator commit, Qwen revision and weight hashes, recipient/submit interaction scaffold, and concise-NL, compact key-value, JSON, and no-communication conditions.
- The next run tests feasibility across widths and whether the format prompts change payloads or receiver behavior. It is not yet a bandwidth-matched sweep or a representative benchmark; multi-turn planning and additional task families remain necessary.
- Ran the four pinned calibration episodes across five arms. Strict per-agent success was 0.25 for scaffold-only and JSON, 0.125 for concise NL and compact key-value, and 0 for no communication. A post-hoc exact arithmetic parser (reported separately from the benchmark evaluator) found semantic answer rates of 0.875, 1.0, 0.75, 0.75, and 0 respectively. All no-communication submissions were wrong.
- The gap is primarily at the terminal interface: for 8-, 12-, and 16-bit inputs, agents often communicated the correct values and computed the correct sum but submitted strings like `723 + 2547 = 3270`, while Silo requires an integer. Do not silently normalize this in the evaluator; track strict tool success and semantic answer correctness as separate outcomes.
- JSON averaged 20.25 UTF-8 payload bytes and 6,187 total model tokens; compact key-value averaged 12.5 bytes but 6,707 tokens. Compact payload length did not imply lower end-to-end token cost. These are four single-seed calibration episodes, not a superiority or scaling result.
- Added `experiments/pilot_v0_3/analyze_duosum_pilot.py` and the public summary `research/DUOSUM_PILOT_V0_3.md`. Next revision: put a bare-integer answer contract in the shared scaffold, reserve held-out seeds for evaluation, and include a binary-string baseline before measuring budget curves.

## 2026-09-27 — Held-out protocol v0.4 frozen

- Prepared a four-episode held-out run using replicate 1 at each DuoSum input width. The common interaction scaffold now requires a bare integer in the terminal tool answer, addressing the output-type failure without changing the evaluator.
- Added a base-2 message condition alongside default/scaffold, concise NL, compact key-value, JSON, and no-communication arms. Message-format arms share the same interaction and answer contract; repeated prompt tokens remain counted.
- Pinned the held-out task IDs, suite manifest hash, simulator revision, model revision and shard checksums in `experiments/pilot_v0_4/policies.json`. The frozen protocol has been committed before any held-out model call.
- Completed all 24 held-out condition-episode runs (four episodes × six conditions). Strict integer success was 0/8 agent submissions in scaffold, concise-NL, compact-KV, JSON, and no-communication, and 1/8 in binary. A verified semantic diagnostic scored 7/8, 4/8, 5/8, 5/8, 6/8, and 0/8 respectively. One greedy episode per width cannot rank conditions.
- The common instruction to submit a bare integer did not reliably change the model's final serialization; agents often submitted equations or omitted the result. This undermines strict task success but does not by itself show that the message representation failed. Keep strict score and semantic score distinct, and do not silently rewrite the benchmark score.
- No-communication failed all four episodes, while each communicating format had at least some semantically correct outputs. This is preliminary evidence that the task instantiated a real communication requirement. Binary averaged 6.5 message bytes, but semantic success was 6/8 and mean total model-token use was 6,296; brevity alone did not establish a useful frontier point.
- v0.4 report: `research/DUOSUM_PILOT_V0_4.md`. Next: freeze a format-neutral deterministic semantic answer evaluator that preserves raw submissions and reports alongside the upstream strict evaluator; then collect more paired seeds/models before attempting budget-matched frontiers.
- Post-analysis trace audit correction: the `binary` condition sent decimal private values in every episode; only 1/8 strings had binary-digit syntax and 0/8 decoded to the sender's value. `json_schema` emitted Python-style single-quoted dictionaries (0/8 parsed as JSON). Thus the previously noted 6.5-byte binary-arm payload is decimal-message brevity, not correct binary coding. Do not interpret either arm as a valid format comparison; future experiments must report syntax validity separately from sender-value fidelity.
