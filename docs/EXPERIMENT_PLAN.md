# Initial experiment plan

**Status:** multiple exploratory model and model-free pilots have been run, but no confirmatory evidence establishes a communication-protocol advantage. Most results so far are capability, harness, or cost-accounting diagnostics. Freeze each concrete protocol before its first model run.

## First benchmark requirement

The model-free Private Match codec frontier now exercises the ideal mixed-radix rank code, ordered tuple, compact JSON, a fixed labeled sentence, independent zlib streams, persistent DEFLATE streams, and a setup-costed shared dictionary on identical role-separated episodes. A five-seed exact compression-horizon follow-up disproved the previous linear break-even extrapolations: the dictionary did not recover its 198-byte setup through 16,384 messages. These remain model-free byte results, not LLM capability or language comparisons. See the frozen [v0.2 codec report](../research/PRIVATE_MATCH_CODEC_FRONTIER_V0_2.md), [measured horizon report](../research/PRIVATE_MATCH_COMPRESSION_HORIZON_V0_1.md), and task runner; model-native token accounting remains gated on a fresh passing capability/resource screen.

The 49-cell [Private Match scaling sweep](../research/PRIVATE_MATCH_SCALING_V0_1.md) varies feature count, vocabulary size, and receiver candidate count with 32 deterministic episodes per valid cell. It verifies the known sender-independent rank-code floor and separates payload growth from receiver-view/context growth. This is a task-family coding-complexity diagnostic, not an LLM scaling law or an agent-count scaling result.

### Three-agent complementary-evidence extension

[Private Match v0.3](../experiments/private_match_v0_3/README.md) gives two senders disjoint coordinates of a hidden target and a receiver the complete candidate table. The one-source and no-message Bayes controls are exact, the fixed-width bit frontier is proven for every total payload budget, and seven representation arms are frozen at `pmt3-prompts-6`, including a prompt-selected AutoForm-style open-format comparator with unknown parse/fidelity diagnostics. A ledger-only selector compares two frozen English templates on eight seed-disjoint development episodes, charges all candidate calls and tokens as setup, and freezes the selected template before evaluation. Calibration, development, and evaluation shards plus an evaluator-only key now exist in the ignored local cache. This remains a synthetic finite task and has no model-backed representation result. Its latest read-only resource preflight was rejected (72.56% mean CPU, 85.26% peak CPU, 3,221 MiB free RAM); no model artifact or service was touched. The endpoint/model settings and perfect full-information receiver calibration are also pending. The task generator uses a 256-bit key with domain-separated HMAC counter streams for table order, candidate IDs, and target selection; bounded draws use rejection sampling. The formal prior is ideal independent-uniform sampling, while a fixed-key shard is a deterministic pseudorandom realization under the HMAC PRF assumption. Keep the key and raw role ledgers private. A separate model-free [prior-shift cohort](../experiments/private_match_v0_3/README.md#exact-prior-shift-episode-control-model-free) checks frozen versus adapted fixed-width codebooks on exact rational target priors; it does not amend or authorize the uniform LLM pilot. Any future model batch still requires a passing resource gate, model/endpoint and tokenizer freeze, and a disjoint full-information receiver calibration. Do not relax the existing gate to obtain a result.

### Separate communication policy from representation

Recent strong alternatives change whether, when, and which agent speaks. S²-MAD reports task-specific token savings by removing low-value exchanges; DALA learns a value-density auction policy; and IMAC jointly learns a message code and scheduler. Budget-matched reasoning work also finds that single-agent self-consistency can be stronger than multi-agent methods at equal compute in some settings. Therefore, a representation comparison must hold the schedule/topology fixed; a policy comparison must hold the representation fixed. Begin with low-overhead controls (no-message, fixed all-message schedule, matched message cap, and a task-specific oracle selector as an upper bound), then consider disagreement/novelty filters only after verifying they preserve unique private evidence and counting selection cost. A single-agent compute-matched arm is required where the task admits one. Score task success against total inference budget as well as channel payload cost. See the literature notes in [`research/RELATED_WORK.md`](../research/RELATED_WORK.md).

The trained-policy baseline set must also include Optima's core challenge: iterative SFT/DPO can jointly improve task outcomes and reduce conversation tokens, with transfer reported across related QA tasks. This means a frozen-model format comparison can support only a frozen-model representation claim; it cannot establish superiority over the best trainable communication system. First establish a reproducible frozen-model frontier on eligible local hardware. If a later study claims general-purpose protocol value, add a task-trained interaction baseline or state explicitly which deployment constraint (such as no fine-tuning, cross-model endpoints, or limited reuse horizon) makes that baseline inapplicable, and include protocol-training/setup cost in the comparison.

Start by reusing existing suites rather than creating another benchmark. Evaluate Silo-Bench's private data shards / algorithmic tasks for scaling and MT-PingEval's private-information games for multi-turn behavior, subject to artifact license and reproducibility checks. Establish communication necessity in each selected split with (a) full communication, (b) no communication, and (c) a centralized oracle/upper bound. Add a small deterministic synthetic task only if these suites do not permit clean message-format/budget interventions.

Retain the PARTNR dialogue extension by Dongre & Hakkani-Tür as a higher-cost future candidate, not the first local benchmark. It provides useful diagnostics—observation/belief convergence, grounded alignment, information novelty, and belief-sensitive messaging—and a negative prior: its tested dialogue conditions reduced action conflicts while task success fell across three hosted LLMs. The paper explicitly excludes linguistic form from its scope, so it does not compare languages. The base PARTNR code is MIT licensed and documents local Llama-3.1-8B use, but we have not located code/data for the dialogue extension itself. Before adoption, verify availability and simulator cost; if reused, preserve silent, synchronous-costed, and asynchronous-free arms, score task success separately from conflict/alignment, and test correct versus deranged message semantics before format comparisons. See the [PARTNR dialogue paper audit](../research/RELATED_WORK.md) and [base PARTNR repository](https://github.com/facebookresearch/partnr-planner).

Use ProMCP as a cost-instrumentation reference when the declared system includes MCP Host/Client/Server orchestration. Its stage-wise accounting shows that planning/schema injection or final answer synthesis can dominate measured workflow cost, depending on deployment topology. This does not imply the same cost shares in a bare agent-to-agent codec study. Continue recording complete prompt/completion and serialized-boundary costs in `tlu.costs.v3`; where the runtime spans components, add per-stage timestamps and attribution instead of folding all latency into a single “communication” number. See the [ProMCP audit](../research/RELATED_WORK.md).

MT-PingEval is not yet a ready-made matched-cost protocol comparison. Its v2 “isotoken” setting evenly partitions 128 whitespace-counted communication tokens per player across 2/4/8/16 turns, excludes internal reasoning tokens, and can leave turns unused; the paper also notes a whitespace/subword mismatch. Any local adaptation must enforce the receiver-native tokenizer cap, separately record all inference cost and actual serialized channel bytes, and audit realized messages/turns. Require correct, deranged-information, no-message, and oracle controls and demonstrate receiver need before interpreting a gain. Its name-game task is a promising source, but the paper reports that multi-turn score growth largely tracks random guess-and-check. The new local [Private Match v0.1](../experiments/private_match_v0_1/README.md) therefore fixes a one-way schedule for representation calibration and generates synthetic records locally; it is not a reproduction of MT-PingEval. Only after that capability gate passes should a separate multi-turn extension test adaptive question/answer value against matched guess-and-check controls. See the detailed [MT-PingEval audit](../research/RELATED_WORK.md#eisenstein-et-al-2026-mt-pingeval-evaluating-multi-turn-collaboration-with-private-information-games).

For an explicit round-depth theory control, retain [pointer chasing](../research/INTERACTIVE_POINTER_CHASING_DESIGN.md) beside the existing one-way `INDEX_m` task. The model-free oracle frontier now contains a direct `k`-turn relay, an explicit parity-assisted Alice-first `(k−1)`-turn protocol for `k>=3`, and a simultaneous full-map upper control; their round conventions must remain separate. The literature supplies a round/bit trade-off under a specified random-function distribution, while Silo-Bench and MT-PingEval supply complementary multi-agent and naturalistic interaction tasks. Do not treat pointer chasing's asymptotic bit theorem as an LLM/token prediction; require deterministic task/oracle checks and a passing model full-information capability gate before model calls, then match total channel-byte caps across turn schedules.

The model-free [exact no-message audit](../research/INTERACTIVE_POINTER_CHASING_NO_MESSAGE_V0_1.md) exhausts all function pairs for `n=2,4` and depths 1–4. At `n=4,k=2` the exact joint no-message upper bound is 0.5, matching the best constant baseline, while the oracle relay is exact. At `n=4,k=3` the no-message upper bound is 0.5762, so use this as a finite prior diagnostic only; larger scales need separately measured no-message model controls. Both agents must submit final outputs, with joint exactness primary.

Potential tasks to retain only if the existing suites leave a concrete gap:

- Distributed constraint satisfaction: agents hold disjoint constraints; only joint aggregation identifies a valid assignment.
- Multi-hop fact synthesis: agents receive non-overlapping evidence and must communicate provenance/conflicts to answer an unseen query.
- Collaborative debugging: agents hold disjoint traces/spec fragments; success requires exchanging the critical interaction.

Avoid tasks that can be solved from public context or common model knowledge alone.

AutoForm's existing HotpotQA split-context setting already demonstrates distributed supporting facts and provides a direct replication target. The paper reports Rouge-L/F1 and says its separate-context token count is the number of tokens generated. The released API wrapper separately tracks prompt and completion tokens for spend accounting. Preserve the reported generated-token metric for comparability, but measure the full prompt/completion/runtime cost and actual channel payload independently; see [`docs/COST_ACCOUNTING.md`](COST_ACCOUNTING.md) and the [AutoForm source audit](../research/AUTOFORM_BASELINE_AUDIT.md). Do not claim communication necessity is previously untested.

## Baseline families

1. Strong natural-language handoff with concise, task-specific prompting; include a model-optimized concise NL version.
2. JSON/schema with explicit required fields and validation.
3. Code or compact symbolic representation where the task is naturally executable/formal.
4. LLM-selected/ad hoc format from Chen et al. (2024), replicated as closely as feasible.
5. Learned task-conditioned format selection (OPTiMACS), task-trained interaction (Optima), and communication-policy controls (I2C-style sender/recipient selection, S²-MAD sparsification, and DALA value-density auction), with format search, task categorization, training, message selection, and inference costs charged. I2C is a trained CTDE MARL policy prior, not a drop-in LLM text baseline; use it to define the selection-control family unless an eligible LLM implementation is available. These policy methods must not be credited as codec gains: hold selected semantic content/schedule fixed when comparing representations, and hold the representation fixed when comparing policies. See the [S²-MAD/DALA audit](../research/COMMUNICATION_POLICY_BASELINES_AUDIT_V0_1.md) and [causal-influence prior](../research/RELATED_WORK.md#causal-influence-and-communication-selection).
6. Shared dictionary / task-specific codebook with setup cost charged.
7. Learned discrete protocol if a reproducible training setup is justified.
8. Latent/KV and weight-space transfer (C2C, LatentMAS, Interlat, CondenseFlow, TFlow, ThoughtComm, DiffMAS, KVComm, and Q-KVComm if its result can be reproduced) where open models, compatible architectures, sufficient resources, and fair serialized-boundary accounting permit runs. Otherwise record the access/compute exclusion and limit claims accordingly. For C2C, count serialized KV bytes and transport separately from its co-located A100 timing, and require private sender evidence for a communication claim. See the [C2C audit](../research/C2C_AUDIT_V0_1.md). For TFlow, charge full sender-prompt forward processing (the public evaluator omits it from TFlow's token metadata), keep the fixed/shared-backbone scope distinct, and require receiver-need tasks with private sender evidence before calling the result communication. See the [TFlow audit v0.2](../research/TFLOW_AUDIT_V0_2.md). For ThoughtComm, report latent payload values/bytes and module setup/inference cost, distinguish identifiability assumptions from semantic grounding, and test the claimed shared/private routing with shuffled-mask controls on receiver-need tasks. See the [ThoughtComm audit](../research/THOUGHTCOMM_AUDIT_V0_1.md). For DiffMAS, additionally freeze task-train/eval split hashes, audit the gradient path and trainable roles, and measure the K×T×d trace at equal byte budgets; its interface-level gradient result does not predict a quality/communication frontier. See the [DiffMAS audit](../research/DIFFMAS_AUDIT_V0_1.md). For Q-KVComm, require item-level task success, a stated dtype/byte denominator including the extracted-facts side channel, and a shape-compatible cross-model cache integration before accepting its compression result. See the [Q-KVComm audit](../research/Q_KVCOMM_AUDIT_V0_1.md). For KVComm, match its receiver-need split-context task family where internals are compatible, but report actual serialized bytes (including anchor tokens) and separate calibration data from scored test episodes; inspect the pinned implementation audit before reproducing its reported ratio. See the [KVComm audit](../research/KVCOMM_AUDIT_V0_1.md).
9. No-communication, full-information, and random-message controls.

Interlat specifically is a learned receiver-dependent latent channel. Keep it outside the black-box text frontier; any eligible comparison must match receiver training and task supervision, add cross-family text as well as latent transfer, report true/other-example/neutral/no-message controls, and sweep quality against serialized tensor bytes and sender-plus-receiver compute. Charge collection, adapter/compressor training, artifact distribution/storage, and amortization. The paper's message-generation latency is not a wire-throughput measurement. See the [Interlat audit](../research/INTERLAT_AUDIT_V0_1.md).

If a learned/emergent protocol is promoted to a comparison, communication success with its training partner is insufficient. Freeze tests on unseen recombinations of known semantic primitives, and require an independent receiver to select the intended held-out target among candidates; held-out signal generation and TopSim do not establish receiver utility. Include held-out tasks, multiple seeds/chains, a holistic codebook control, semantic-fidelity and corruption/recovery measures, and charge negotiation/transmission plus decoding cost. Report structural measures such as TopSim or n-gram reuse as diagnostics, not as proof of compositional semantics. Resolve the prior study's source-level inconsistency (one target plus four distractors versus 25% chance) against any available executed candidate generator, and derive Tacit's chance baseline from its own candidate distribution. See the [emergent-communication audit](../research/RELATED_WORK.md#emergent-communication-compositionality-and-iterated-learning) and [held-out utility audit](../research/EMERGENT_OOD_UTILITY_AUDIT_V0_1.md).

## Core controlled comparisons

- Same underlying model weights and task episodes while varying only representation; then vary receiver model and model family.
- Sweep the **channel budget** using delivered UTF-8 bytes and, separately, receiver-tokenizer message tokens; include transmitted schemas/codebooks and state any preinstalled shared side information. Separately report **full inference cost** for every agent call (all prompt and completion tokens, including repeated context, instructions, final answers, retries, and failures), plus runtime and setup. Compare equal channel budgets, quality-versus-inference-cost frontiers, and matched-quality operating points where supported. See [`docs/COST_ACCOUNTING.md`](COST_ACCOUNTING.md).
- Fix and report turns, wall time, tool calls, model calls, temperature, prompt, and maximum rounds. On MT-PingEval, compare one-shot against multiple turns at the same overall budget.
- Hold task context, agent count, information partition, number of turns, decoding settings, and answer evaluator constant.
- Separate content messages from instructions, schema definitions, codebook negotiation, shared prompt context, and hidden-state transfer in the record; charge communicated/setup components to the relevant channel or reuse-horizon budget, and repeated prompt components to inference cost.
- For learned format selectors, also record task-classification calls, candidate-format generation/search, exploration trajectories, selector state size, and per-message selection latency; report break-even reuse horizon separately from message-format cost.
- Measure decode success, semantic reconstruction, task completion, correctness, latency, generated and consumed tokens, bytes on the wire, setup cost, and retries.
- For robustness, separate transport corruption/truncation, semantic decode error with intact bytes, and task-execution error; compare redundancy and repair at equal total forward-plus-reverse bytes, model calls/tokens, and round caps. Do not attribute semantic failures to the physical channel. See the [channel-robustness audit](../research/CHANNEL_ROBUSTNESS_AUDIT_V0_1.md).
- Sweep task complexity, context length, agent count, rounds, and information partition to test scaling, not just one fixed benchmark.

## Initial predictions

- If gains are only output brevity, equal-byte/equal-token quality curves will erase them.
- If gains depend on shared prior/task-specific conventions, unseen receivers/tasks will reduce them; charging setup will create a horizon-dependent crossover.
- If the task bottleneck is an exact symbolic constraint, typed structured forms may dominate prose; if the evidence is uncertain/contradictory, confidence/provenance and recovery may matter more than raw density.
- Under tighter budgets, compression should first improve success, then hurt as distortion and decoding errors dominate.

## Analysis and reporting

Use repeated seeds/episodes, paired comparisons on the same examples, bootstrap uncertainty intervals, and disclose all exclusions. Report the full Pareto frontier and bootstrap uncertainty for key frontiers; avoid selecting a protocol from a single aggregate score. Track failures by ambiguity, omission, hallucinated inference, schema/decode error, receiver mismatch, and error propagation.

## Local feasibility

The machine currently exposes an RTX 4060 with 8 GiB VRAM and about 32 GiB system RAM. Start with small open instruction models and deterministic symbolic environments. Do not assume full fine-tuning or large multi-agent models fit. API-backed models may be an optional later replication, not required for core reproducibility.
# Research update: exact-sum benchmark candidate

The first Silo-Bench run showed that task names and formats do not guarantee communication necessity. A next benchmark candidate is two-agent exact sum: each agent receives a private positive integer and both must submit the total. Neither private value alone determines the answer. Use varying input widths and multiple deterministic seeds, with a no-communication control on every task. This isolates the communication channel from long-chain reasoning, but is intentionally a low-complexity calibration task, not the final benchmark.

For two private integers from a domain of size \(M\), exact sum requires at least \(2\log_2M\) bits of worst-case deterministic binary communication when both agents must output the sum; for power-of-two domains, sending each input once attains the bound. This gives a known wire-bit floor. Model-token, payload-byte, repeated-context, decoder, and setup costs remain separate and are not directly bounded by that proposition. The task is a probe of protocol overhead and receiver fidelity, not a claim that sum aggregation is representative of all agent work.

Promotion gate: generate exact task JSON from a pinned seed; verify per-agent observation does not determine the sum; verify every model condition against the exact answer; measure how often communication is actually used and whether the no-communication control fails; then add more complex task families before any language claim.

## v0.4 outcome and next gate

In four held-out episodes, no-communication semantic success was 0/8 agent outputs; communicating conditions ranged from 4/8 to 7/8. This supports continuing the task as a communication-necessity probe, not as a format ranking. Strict benchmark success was nearly zero because the model often submitted an equation rather than the required integer even after a common instruction. A trace audit found only 1/8 binary-arm messages had binary-digit syntax and 0/8 decoded to the sender's value; 0/8 JSON-arm messages parsed as JSON. The labeled arms mostly sent decimal strings and all JSON-arm messages used single quotes. These instruction-adherence failures mean their measured payloads/outcomes cannot be interpreted as binary/JSON efficacy. The next protocol must preserve raw messages/submissions and report syntax validity, sender-value fidelity, upstream strict scores, and a frozen, format-neutral semantic score. Freeze and validate the evaluators before new model calls. Then use more paired seeds and at least one additional local model; only proceed to matched communication budgets if task completion is reproducible in conditions that actually follow their representation instructions.

## v0.5 preregistered diagnostic

The v0.5 protocol uses the remaining two held-out replicates per width (eight episodes), retains the v0.4 controls, adds an AutoForm-style model-selected format, and adds explicit examples to JSON and binary instructions. The AutoForm wording is adapted from the released configuration in [AutoForm's official repository](https://github.com/thunlp/AutoForm). This arm has no fixed syntax target. All arms retain the same interaction and terminal-answer instruction, and the local semantic grader does not rewrite raw outputs. The policy pins prompts, cases, model, weight hashes, and engine before any new model call.

**Prediction:** if v0.4's JSON/binary failures mainly came from unclear instructions, examples should improve syntax validity and sender-value fidelity. That may not improve semantic task success or total token use. If those formats remain unused or misdecoded, this local model/setup cannot fairly estimate their representational efficiency. Eight tasks on one 1.7B model remain exploratory; budget sweeps wait for reliable execution and a second receiver model.

**Observed v0.5 result:** semantic exactness was 15/16 scaffold, 11/16 concise-NL, 10/16 compact-KV, 4/16 JSON, 13/16 binary-labeled, 12/16 AutoForm, and 1/16 no-communication. ## v0.7 PrefixSum transfer

The v0.6 result is compatible with useful compact scalar messages, but DuoSum only requires one agent to add one hidden integer. The frozen v0.7 suite adapts Silo-Bench II-11 Prefix Sum to two agents, with 6-, 15-, and 30-value segments and four seeded cases per length. It uses the exact v0.6 Qwen3-4B Q4_K_M/llama.cpp setup and seven arms: free-form shared scaffold, prescribed concise English subtotal, compact `s=<sum>`, JSON subtotal, binary subtotal, full-shard JSON list, and no communication.

For a segment of length (L) with values in ({1,ldots,50}), Agent 1's target depends on Agent 0 only through (S=sum_i x_i). There are (49L+1) possible subtotal values, so an exact fixed-length encoding needs at least (lceillog_2(49L+1)
ceil) bits in the worst case (9, 10, and 11 bits for the tested lengths). This lower bound predicts that subtotal messages can be much smaller than the full shard, but it does not predict whether model agents can compute, encode, decode, or use them reliably.

The falsifiable prediction is conditional: if compact-KV/binary messages accurately carry the subtotal, they should beat full-shard messages on payload bytes; the full-shard arm may still yield higher task success if arithmetic aggregation or decoding is a bottleneck. No equal-token budget, efficiency-frontier claim, or scaling law is part of v0.7. The task generator validates exact local and distributed prefix outputs plus Agent 1's information insufficiency. See [`experiments/pilot_v0_7/policies.json`](../experiments/pilot_v0_7/policies.json).
